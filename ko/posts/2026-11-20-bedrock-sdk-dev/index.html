Minecraft Bedrock의 Mod 개발 환경을 전부 직접 제작한 이야기 | SDK, 자동 테스트, 실기 충돌의 근본 원인

PRPEXServer 공식 포털자택 서버, 로컬 LLM, Minecraft 모드 개발 포털 사이트는 여기입니다

결론을 먼저

  • Minecraft Bedrock(Windows 버전)의 클라이언트 Mod를 만들기 위한 SDK를 제로(0)부터 직접 제작하여 운영하고 있다
  • 게임 업데이트 추종은 "시그니처 스캔 + 차분 예측"으로 시스템화했다
  • 테스트는 Linux 상에서 Windows 버전 게임을 헤드리스로 무인 실행하는 환경을 구성하고, AI 에이전트에게 돌리고 있다
  • 가장 큰 적은 실기에서만 발생하는 크래시였으며, 근본 원인은 "게임 측 할로케이터로 확보된 메모리를 Mod 측 런타임이 해제했기" 때문이었다

SDK를 직접 만드는 이유

Bedrock 클라이언트 Mod는 공식 메커니즘이 서버 측 스크립트 API 중심이므로, 클라이언트 측 렌더링이나 입력에 접근하려면 네이티브 DLL을 주입하는 수밖에 없습니다. 기존 SDK도 몇 가지 있지만, 버전 추종 속도와 원하는 API 형태를 우선하여 직접 제작하기로 했습니다.

현재 SDK는 함수 주소를 버전별로 "시그니처(기계어 패턴)"로 찾는 방식입니다. 게임이 업데이트되어도 패턴이 남아 있다면 자동으로 추종할 수 있습니다.

버전 추적 메커니즘

새로운 버전이 나오면 할 일이 정해져 있습니다.

  1. 구 버전에서 알고 있는 주소 주변 바이트열에서 새 버전 실행 파일을 스캔하여 후보를 찾습니다
  2. 찾지 못한 것은 인접 함수의 이동량(델타)으로 예측하여 맞춥니다
  3. 모든 심볼이 해결되면 실제로 주입하여 동작을 확인합니다

최근 버전 대응에서는 74개 심볼 전체를 이 절차로 이식했습니다. 지루하지만, "매번 수동으로 역어셈블과 씨름하는" 것에서 해방되었습니다. 막히는 지점도 있어서, 주소 목록 형태의 값은 스칼라 값 재배치에서 누락되거나, 프로파일 캐시가 임베디드 데이터보다 우선되어 "고쳤는데 안 고쳐지는" 상황 등은 절차서에 정리해 두었습니다.

자동 테스트 환경: Linux에서 Windows 버전을 무인으로 실행

모드 동작 확인을 매번 수동으로 하는 것은 한계가 있어 테스트 환경도 구축했습니다.

  • Linux 기기 위에서 호환 레이어를 통해 Windows 버전 Bedrock을 실행하고, 가상 디스플레이로 헤드리스 실행
  • DLL 주입, 서버 참여, 채팅을 통한 명령어 실행, 화면 스크린샷 캡처까지 모두 스크립트화
  • 검증용 Bedrock 서버(BDS)도 동일 장비에 구축하여, 참여부터 채굴/제작과 같은 일련의 동작까지 무인으로 확인할 수 있습니다.

이제 AI 에이전트에게 "수정하고, 테스트하고, 증거를 남기라"고 완전히 맡길 수 있게 되었습니다. 사람은 아침에 일어나 결과를 읽기만 하는 운영이 이루어지고 있습니다.

다만 자동 테스트를 통과해도 실제 기기에서 다운되는 경우가 있습니다. 다음이 그 이야기입니다.

실기에서만 발생한 크래시의 근본 원인

특정 Mod에서 실제 Windows 환경에서는 명령어 실행 직후 반드시 크래시가 발생하지만, 자동 테스트 환경(호환 레이어 위)에서는 재현되지 않는 문제가 있었습니다.

근본 원인은 메모리 할당자 경계 침범이었습니다. 게임 내부 함수가 "요소 배열을 반환"할 때, 해당 메모리는 게임 측 할당자로 확보됩니다. 이를 Mod 측 C++ 런타임이 일반적인 방식으로 해제하면 힙이 손상되어 다운됩니다. 호환 레이어 위에서는 우연히 노출되지 않았을 뿐, 실제 환경에서는 확실히 죽는 지뢰였습니다.

대책은 반환된 배열 내용을 자체 배열로 복사하고, 원래 버퍼는 게임 측 해제 함수로 반환하는 것입니다. 이 "숨겨진 반환값으로 컨테이너를 반환하는 ABI는 모두 이 지뢰"라는 교훈을 동일한 형태의 모든 함수에 전파했습니다.

교훈은 간단합니다. 자동 테스트 통과와 실제 환경 구동은 별개입니다. 따라서 지금도 최종 확인은 실제 환경에서 진행하며, 자동 테스트 결과를 "실제 환경에서 증명됨"이라고 말하지 않도록 하고 있습니다.

현재 만들고 있는 것

SDK는 현재 호환성을 버리고 전면적으로 새로 고치고 있습니다. 핵심은 TypeScript로 Mod를 작성할 수 있는 플러그인 시스템이며, DLL 하나를 주입하면 호스트가 되고 폴더에 놓인 Mod가 자동으로 로드되는 형태를 목표로 하고 있습니다. 설정 화면에 고유 항목 추가(게임 설정 UI에 Mod 설정 혼합) 및 키 할당의 공식 API화도 진행하고 있습니다.

요약

  • 버전 추종은 "시스템"으로 하면 빠르다. 주관적인 역어셈블 작업을 절차화했다
  • 자동 테스트 환경은 강력하지만, 실기에서만 발생하는 문제는 반드시 있다. 전제로 나누어 생각한다
  • 타인의 할로케이터 메모리를 해제해서는 안 된다 (당연하지만 언급했다)
