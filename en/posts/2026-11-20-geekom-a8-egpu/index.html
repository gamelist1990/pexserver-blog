When I attached a used GPU externally to a mini PC, local LLMs reached practical levels | GEEKOM A8 + AG02 + RTX 2080 SUPER measured results

Conclusion First

  • Attached an eGPU dock "AG02" and a used RTX 2080 SUPER to the mini PC "GEEKOM A8". Total cost 63,200円
  • Local LLM generation speed is up to approx 116 tok/s, and for the model currently in production, it is approx 113 tok/s (parallel 3)
  • For the purpose of running my Discord Bot's AI locally 24 hours a day, I was able to graduate from cloud APIs

This article answers the question, "Is attaching a used GPU really practical?" with actual measurements.

Why I did it

I built and operate an AI Bot that runs constantly on a Discord server. Initially, I used cloud APIs, but,

  • Costs increase the more I use it
  • Hits rate limits
  • Cannot freely test models or parameters

These dissatisfactions accumulated. "If I'm going to keep it running constantly anyway, I want to run the model locally." The thing I focused on was the mini PC on my desk, the GEEKOM A8.

Purchased Items

Item Price Notes
Palit RTX 2080 SUPER X 8GB 28,800円 Amazon Renewed (Refurbished)
AG02 (eGPU dock) 34,400円 Supports both USB4 / OCuLink
Total 63,200円

There are three selection points.

  1. Prioritize NVIDIA: Many local LLM ecosystems are based on CUDA, meaning the amount of information during troubleshooting is vastly superior.
  2. Accept 8GB VRAM: Since the purpose is testing, I started small.
  3. Return/Warranty Conditions: This unit is returnable until January 31, 2027, and the seller warranty is at least 180 days. Since I am wary of initial defects in used GPUs, I prioritized "being able to return it if it fails" over "low price."

GEEKOM A8 specifications

  • CPU: Ryzen 7 8845HS
  • Memory: 16GB × 1 (DDR5-5600) *1 free slot
  • Connection: USB4 (40Gbps) only. No OCuLink

Since there is no OCuLink, the bandwidth limit is 40Gbps via USB4. This was the biggest concern, but since LLM inference is a process where "once the model is loaded into VRAM, the rest is completed within the GPU," it did not prove to be a fatal bottleneck in actual measurements (see below).

What I did during setup

  1. Connected 2080 SUPER to AG02 and connected to A8 via USB4
  2. Installed NVIDIA driver 580.178.04 + CUDA 12.4.131
  3. Built llama.cpp using the CUDA version and performed inference
  4. Fan control: In a headless environment, the GPU fan wouldn't spin, causing crashes due to heat, so I created a persistent service to run at a fixed 50% → Stable at 73℃

Item 4 is subtly important; if you want to run an external GPU "unattended like a server," temperature monitoring and fan control should be addressed first.

Measured Results

Measurements were taken using the CUDA version of llama.cpp.

  • Generation speed: 86.6 ~ 115.9 tok/s (depending on model and settings)
  • Prefill (input processing): approx 4,465 tok/s

The configuration currently used in the production Bot is as follows.

  • Model: Gemma 4 E4B
  • Operating with generation of approx 113 tok/s, 3 parallel requests

The response speed for the ChatBot is more than sufficient, and subjectively, it is comparable to the cloud API era. The only cost is electricity.

Among those tested, Gemma 4 12B (UD-Q3_K_XL quantization, non-QAT) was quite comfortable for a 12B class model, achieving approx 54 tok/s with 128K context + MTP enabled. The biggest takeaway is that "even with 8GB VRAM, this level is achievable depending on quantization and model selection."

Pitfalls/Points to Note

  • Memory is 16GB × 1 stick: It is insufficient for using models cached in RAM. Expansion is on hold pending price review (not a price that forces purchase)
  • A8 NPU cannot be used: It is on the chip, but disabled in the BIOS and not visible to the OS. Even if enabled, since it is a generation outside the scope of the current runtime, it cannot practically be relied upon for LLM use.
  • Used GPUs have individual variations: Fan noise or coil whine is luck. Therefore, it is important to check the return conditions first.

Summary: Who is it suitable for

  • Suitable people: those running always-on self-built bots, those who want to convert API charges into fixed costs (electricity), and those who can manage the risks of used hardware
  • Unsuitable people: those who want to run the latest large models at maximum performance (they should just buy a new GPU)

Although it's a strange combination of "mini PC + used eGPU," having "your own AI foundation" for just over 60,000 yen was more comfortable than expected when I tried it.
